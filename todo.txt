Define design language
- UI Elements
  - Total uniform design language between CommanderDog and its Chewtoys.
  - Header with header-buttons - all buttons the same look and feel, size and layout.
  - Close, Minimize, Maximize, Dock -buttons to follow the same design, like the close button, neat, petite, subtle.
  - Tab/Panel header-buttons: Follows the same design as today, define the design and lock it.
- Main Header
  - Main header buttons and navigation
	- Buttons are right aligned in the header, profile button most right, apps left of, and tasks left of apps.
	- Left space in header are branding.
  - badge close to the branding with customizable color and name, but by default reads the hosts hostname. Also customizable shape and size. For users with multiple hosts running CommanderDog, or actually change "CommanderDog" to whatever you want like hostname etc. Why choose. We can do both! Dependant on tier - licensing.
- Tab/panel - aka just Panels now, tabs are for settings.
  - Panel header buttons and navigation
    - Rearrange some of the buttons - need to think more.
- Chewtoys (apps/plugins/extensions)
  - Close, minimize/maximize, dock/float -buttons. Neat, subtle buttons, as current close button.
  - Action buttons to follow CommanderDog header action button design
  - In PC viewport Chewtoys should be resizeable and dockable. Phone and Tablet viewport they should open as overlaying app, with minimal/subtle header-buttons.
- Colouring/color scheme "Amber":
  - Background of dropdown boxes are white text on white background when "open" - must fix.
  - Two tone border colors - only under more settings, and direction, diagonal left/right, horisontal, vertical, circle.
